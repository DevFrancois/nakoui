# Tab bar reflections and Carousel

The tab bar uses one custom Metal capsule on every tab. `TabBarOptics.metal` supplies the surface tint, sharp rim, soft glow, warm/cool lighting and slight edge darkening. The material has uniform 88% base opacity, with a light or dark neutral tint. The default Face and edges mode adds a soft nearby-color wash across the face and stronger reflections at the rim; Mostly edges keeps the same neutral face and disables only the wash. There is no `UIGlassEffect` or `UIGlassContainerEffect` in the tab bar.

Reflection normalization counts only geometrically available sampling regions. Off-screen rays and the capsule's feedback exclusion no longer dilute valid colors from the other side. Source alpha still attenuates genuinely translucent content. Two-texel coverage fades and an explicit footprint confidence prevent abrupt changes at moving clipping boundaries without canceling that fade during normalization. Output remains encoded-premultiplied sRGB for Core Animation.

The face wash uses one reusable 64×1 `rgba16Float` texture, with nine nearby-source samples per texel. The field is prepared and sampled on the existing Metal command queue using tracked resource hazards; the capsule makes one field lookup per face fragment. Mostly edges, zero wash, and Reduce Transparency skip the wash pass. Pipelines and the scratch texture are allocated once. Capture dimensions, image preparation, texture pools and deadline scheduling are unchanged by tuning.

Debug builds show the controls directly in Profile, with a fixed color/photo strip beside the actual menu while the controls scroll. All 14 parameters and the mode live in one root-owned `TabBarReflectionTuningStore`; only the editor and tab-bar bridge observe them. The renderer receives an immutable `TabBarReflectionSettings` snapshot, and the next display frame applies it through uniforms without changing renderer identity, tab labels, layout, capture history or Carousel leases. Values save after 250 ms of inactivity, and flush when editing ends or the scene becomes inactive. Reset restores Face and edges and every default in `TabBarReflectionSettings`. Both modes share values, including the disabled face-wash slider. Release builds exclude the editor/store and always use the new defaults, ignoring development preferences. Reduce Transparency overrides either mode with an opaque surface and suppresses sampled colors.

Ordinary UIKit/SwiftUI content feeds this shader through `TabBarUITextureCapture`. `TabBarLayerRegionRenderer` walks one presentation-layer tree, propagates affine transforms, and rejects offscreen subtrees before drawing the nearby region into reusable IOSurface-backed pixel buffers. Plain layout containers can be split. Empty rounded containers leading through safe empty wrappers to one image/drawing leaf use cached native corner coverage, including continuous and selected corners; the current image placement is rendered each time. The immutable mask cache is bounded to 16 entries and 512 KiB. Arbitrary masks, group opacity, perspective, rounded groups with overlapping children and other complex groups retain Core Animation's original subtree rendering. The live view/layer tree is never modified. A clipped hole excludes the capsule and its controls to prevent recursive reflections.

Supported public `CGImage` photo sources are prepared once into sRGB-premultiplied images up to 256 pixels per side. A serial background worker performs decoding and resampling; the main actor owns cache lookup, admission and live layer geometry. `ArticleThumbnailImage` prewarms this same cache when assigning its image, before it reaches the reflection crop. The cache retains source identity and is bounded to 16 entries and 32 MiB of estimated source-plus-prepared raster storage, including in-flight work. At most eight preparations can be pending; visible misses take priority over queued prewarming. Repeated pending requests and failures do not enqueue duplicate work.

Each capture reapplies the current layer bounds, aspect-fill gravity, clipping and opacity; scrolling changes image placement without decoding and resampling the full asset again. Replacing an image selects a new entry. A supported image that is still preparing contributes no image pixels for that capture, while the rest of the current UI continues rendering. Capture never waits for preparation, decodes the full image as a synchronous fallback, or substitutes another image's stale pixels. Unsupported source formats, mappings and compositing keep native rendering. This is an image-source cache, not a cache of old UI frames.

The UI color field is bounded to 160 pixels on its long edge; the capsule contour still renders at display resolution. Captured UI pixels require no intermediate UIImage, CGImage, CPU pixel copy or texture upload. Core Graphics writes encoded premultiplied BGRA into shared storage exposed as a raw `bgra8Unorm` texture. A GPU preparation pass decodes each new capture once into a cached linear-premultiplied `rgba16Float` texture, so the rim's many samples do not repeat color conversion. Both pools have four bounded slots and track in-flight reads before reuse.

This is a nearby-color source, not a complete replacement for UIKit's compositor. Publicly identifiable text layers, UILabels and alpha-only image masks are omitted. SwiftUI does not expose every text run that way, so not all SwiftUI text is excluded. Custom/compositor effects can differ from their on-screen appearance, and ordinary video/Metal layers need a direct texture producer. Capturing still costs main-thread time; a small output alone does not make traversal free.

`TabBarCaptureCadence` measures this cost, allows up to 60 fresh UI captures per second within a 60% capture-work budget, and avoids a capture when it is likely to miss UIKit's submission deadline. The deadline comes from the current view's `UIUpdateInfo.completionDeadlineTime`, with the display-link target as a fallback when UIKit update information is unavailable or invalid. It never adds a synthetic frame of budget, and an already-past UIKit deadline is still respected. It queues no backlog. Cost history ages by elapsed time when a successful capture supplies a new measurement, so one expensive image does not trap later inexpensive content at the 250 ms retry cadence. Waiting alone never lowers the estimate or relaxes the deadline.

One UIKit display-link clock drives capture and rendering; on iOS 27 it targets the window scene. The tab bar reuses Carousel's `CarouselDrawableBroker`, the helper behind Debug → Performance → Responsive rendering. Capture admission happens before requesting a drawable. The broker acquires `nextDrawable` and commits commands on a serial worker, keeping one replaceable pending request. It encodes the latest UI textures, geometry and settings when a drawable becomes available, so a driver wait cannot queue stale reflection states or block touch handling. `CAMetalLayer.presentsWithTransaction` sends the surface through Core Animation's normal presentation mechanisms. After the command is scheduled, the main thread validates its generation and presents inside a transaction; it never waits for scheduling. Commands reserve their queue order before the worker commits them, and GPU completion independently releases texture leases. Drawable size changes happen only in the broker's idle preparation phase. Appearance, geometry and lifecycle changes invalidate obsolete presentations; tuning changes do not.

The display link stops when the surface detaches or the app becomes inactive and is recreated when its window scene changes. Two captured frames blend over at most 33 ms using presentation timestamps; this is color interpolation, not synthesized motion. A costly hierarchy can still reduce fresh UI sample frequency. Device measurements determine actual performance; GPU completion rate alone does not establish smooth UI reflection updates.

Carousel is temporarily in Search for debugging, with three local poster/video pairs: home insurance, Mexico City and spending. Its renderer and videos pause when Search is inactive. It supplies live card and video pixels through:

```swift
CardCarousel.onRenderTexture(_:onUnavailable:)
```

The callback lends a scene texture and its uncommitted command buffer. The tab bar appends a GPU copy of the visible nearby crop (at most 320 pixels on its long edge) to that same buffer. After completion, a consumer-owned copy can be sampled on subsequent display frames. Three bounded scene slots remain leased until both the producer write and all presentation reads finish. The original pooled scene is never held for a later GPU read; the consumer never commits the producer's command buffer or creates a duplicate video player. No CPU readback occurs on this path.

The shader blends previous/current UI captures in window coordinates, then composites the direct Carousel crop only inside its visible screen region. Both feeds contribute nearby colors to the same optical material. Native Carousel companion overlays belong to the UI capture rather than its Metal texture. `onUnavailable` removes only the direct scene contribution; ordinary UI continues reflecting.

`RootTabContent` owns `tabBarReflectionSource` and supplies it through the environment. Search already connects. `TabBarReflectionConnection.swift.example` shows how to connect a configured Carousel elsewhere under the same root and window.

`Configuration/AppInfo.plist` opts supported iPhones into high-refresh display links. The OS still chooses the available refresh rate. Background and detached surfaces stop requesting frames; Reduce Transparency uses an opaque custom material without UI capture.

### Appearance compared with `83b5621`

Before the live-tuning change, matched dark Articles screenshots showed that `83b5621` had a visibly stronger rim than `eca5a74`. Three source changes explained the difference: the center absorbed more background light for readable controls; the nearby-color term was multiplied by the fraction of all sampling rays that found source pixels, reducing strength where rays left the screen or entered the cleared feedback hole; and output had been corrected to encoded-premultiplied sRGB for Core Animation. The old output encoded already-premultiplied linear values, which could produce RGB bytes greater than alpha and overbright edges. The UI color field was also reduced from 384 to 160 pixels, softening small source details. The new material restores strong colors through geometric eligibility normalization and adjustable rim/face lighting, while retaining the smaller capture and correct encoding. The reference Duo runs iOS 27.2 and the current Duo runs iOS 27.1, so screenshots alone do not isolate OS effects; the shader changes are directly established by the commit diff.

## GPUI glass study

The reference at `/Users/francois/Downloads/Carousel/gpui-glass-demo` owns the entire UI renderer. Its `BackdropContext` lends an existing scene texture and command encoder at the correct draw-order position; background text is already in that texture, while glass foreground controls draw afterward. This avoids the UIKit acquisition cost rather than hiding it with a different shader.

Its reflection pipeline separates a coarse exterior radiance field (roughly four logical pixels per texel) from detailed edge geometry, prepares reusable GPU fields, and tracks damaged regions. The coarse color field and decode-once preparation above follow that separation of source detail from optical contour quality. Carousel already provides the analogous direct GPU callback. GPUI's source-damage tracking cannot be assumed for arbitrary UIKit content, so cached UI captures must still be refreshed. No GPUI source code has been copied into this implementation.

A second review focused on Articles. In `vendor/gpui-ce/crates/gpui/src/window.rs`, `paint_image_with_corner_smoothing` caches decoded image bytes in the sprite atlas by image ID and animation-frame index, then draws the visible texture subrectangle with rounded geometry. This ownership is the transferable idea: `ArticleThumbnailImage` exposes the feed's existing asset through a persistent `UIImageView` with the same centered aspect-fill crop, and the bounded prepared-image cache above reuses those pixels for reflection capture. A public image backing alone did not remove the measured cost; preparing and reusing its pixels is also necessary. The gallery keeps `ArticleHeroImage`, preserving its SwiftUI `ImageRenderer` backdrop sampling.

GPUI's incremental bleed damage in `crates/gpui-glass/src/glass.rs` applies between consecutive glass surfaces within the same frame; its renderer starts each new frame fully invalidated. It does not justify reusing old UIKit pixels based on layer identity or `needsDisplay`. Further candidates are capture bounds derived from the shader's actual sampling radius, footprint-filtered Carousel downsampling, and a prepared edge field. Those address separate costs and fidelity concerns; none supplies SwiftUI's missing compositor texture or removes expensive CPU image rendering by itself.
